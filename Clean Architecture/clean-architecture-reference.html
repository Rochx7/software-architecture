Como identificar o que pertence a cada camada, seguindo os princípios de Robert C. Martin (Uncle Bob). A regra de dependência é o núcleo de tudo: as setas sempre apontam para dentro.

Visão geral

As camadas concêntricas

Cada anel só pode conhecer o anel imediatamente interno. Quanto mais para fora, mais a camada sabe sobre tecnologia; quanto mais para dentro, mais ela sabe sobre regra de negócio.

Entities — regras de negócio puras
Use Cases — orquestração
Gateways — contratos/portas
Infrastructure — implementação concreta
Controllers — entrada HTTP
Camada 1

Entities — Enterprise Business Rules

O centro do sistema. Contém as regras de negócio mais fundamentais, aquelas que existiriam mesmo sem nenhum software.

01
Entities
src/domain/entities/User.ts
src/domain/entities/User.ts
export class User {
  constructor(
    public readonly id: string,
    public readonly name: string,
    public readonly email: string
  ) {}

  changeName(name: string) {
    if (!name) throw new Error('Nome obrigatório')
    this.name = name
  }
}
  • Contém regras de negócio puras
  • Não conhece banco de dados
  • Não conhece API
  • Não conhece frameworks
Teste mental
Se essa classe existiria mesmo sem Node.js, sem banco e sem HTTP — ela pertence aqui.
Camada 2

Use Cases — Application Business Rules

Representam uma intenção do usuário. Cada Use Case orquestra as Entities para executar uma ação específica do sistema.

02
Use Cases
src/application/useCases/CreateUserUseCase.ts
src/application/useCases/CreateUserUseCase.ts 
export class CreateUserUseCase {
  constructor(
    private userRepository: UserRepository
  ) {}

  async execute(input: CreateUserInput) {
    const user = new User(
      crypto.randomUUID(),
      input.name,
      input.email
    )

    await this.userRepository.save(user)

    return user
  }
}
  • Orquestra regras de negócio
  • Executa uma ação do sistema
  • Representa uma intenção do usuário
  • Não conhece banco específico
Regra prática
Se a ação pode ser descrita por um verbo de negócio, provavelmente é um Use Case.
CreateUser UpdateUser DeleteUser GenerateReport CalculateRetirement
Camada 3

Ports / Gateways

São contratos — não implementações. Definem o que o sistema precisa fazer, nunca como isso será feito.

03
Gateways
src/application/gateways/UserRepository.ts
src/application/gateways/UserRepository.ts 
export interface UserRepository {
  save(user: User): Promise<void>
  findById(id: string): Promise<User | null>
}
  • Define contratos
  • Não possui implementação
  • É uma porta de saída
  • O Use Case depende dela
Gateway é
"O que o sistema precisa fazer" — nunca "como será feito".
Camada 4

Infrastructure

Implementa os Gateways com tecnologia real. É a camada mais substituível de todo o sistema.

04
Infrastructure
src/infra/database/PostgresUserRepository.ts
src/infra/database/PostgresUserRepository.ts 
export class PostgresUserRepository
  implements UserRepository {

  async save(user: User) {
    await prisma.user.create({
      data: {
        id: user.id,
        name: user.name,
        email: user.email
      }
    })
  }

  async findById(id: string) {
    return prisma.user.findUnique({
      where: { id }
    })
  }
}
  • Implementa o Gateway
  • Conhece Prisma
  • Conhece PostgreSQL
  • Pode ser trocada por MongoDB sem alterar o Use Case
Camada 5

Controllers

A porta de entrada HTTP. Recebem a requisição, chamam o Use Case correto e devolvem a resposta — nada além disso.

05
Controllers
src/interfaces/http/UserController.ts
src/interfaces/http/UserController.ts
export class UserController {
  constructor(
    private createUserUseCase: CreateUserUseCase
  ) {}

  async handle(req: Request, res: Response) {
    const user =
      await this.createUserUseCase.execute(req.body)

    return res.status(201).json(user)
  }
}
  • Recebe HTTP
  • Chama Use Case
  • Retorna resposta
  • Não contém regra de negócio
O princípio central

Dependency Rule

As dependências de código-fonte sempre apontam para dentro. A implementação concreta depende da abstração — nunca o contrário.

Controller
recebe HTTP
↓
Use Case
orquestra a regra
↓
Gateway (interface)
define o contrato
↑
Repository (implementação)
Postgres, Mongo, etc.
As dependências sempre apontam para dentro

Fixando o conceito

O que é (e o que não é) cada peça

O que é um Use Case?

  • Uma ação do sistema
  • Possui um verbo
  • Orquestra regras de negócio
  • Não conhece tecnologia

O que é um Gateway?

  • Uma abstração
  • Um contrato
  • Representa algo externo
  • Banco, API, cache, mensageria

O que NÃO é um Use Case?

  • Prisma
  • Axios
  • SQL
  • Express
  • React

O que NÃO é um Gateway?

  • Uma implementação concreta
  • Uma classe que conhece Prisma diretamente
  • Uma chamada HTTP com Axios embutida
